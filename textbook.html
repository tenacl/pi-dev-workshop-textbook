1장. 빌려 쓰는 AI에서, 가지는 AI로

Part 1 · 컨셉
🏛️ 다산 원칙
본의본령법 本意本領
핵심을 건드려 전체를 움직여라. 이 교재의 진짜 한 줄을 먼저 박는다. "내가 만들고, 내가 가진다."

핵심 개념

이 워크샵의 한 줄 컨셉은 단순하다. 빌려 쓰는 AI에서, 가지는 AI로. ChatGPT 창에 들어가서 매번 같은 페르소나 프롬프트를 다시 붙여넣고, 같은 첨부파일을 다시 올리고, 같은 톤을 다시 설명하는 것 — 그건 빌려 쓰는 AI다. pi.dev로 만든 한 채는 그 박제 가능한 것(컨텍스트, 슬래시 커맨드, 호출 능력, 외부 시스템 연결)을 파일로 만들어 본인 시스템에 둔다.

🎭 강의용 비유 (pi 공식 표현 아님)

이 워크샵은 두 개의 비유를 겹쳐 쓴다. 프로젝트 아라(모듈러 스마트폰)와 소설가가 캐릭터를 글로 박제하는 작업. "내가 조립한 하드웨어 위에 내가 쓴 영혼이 박힌 에이전트" — 이 감각이 워크샵의 정서적 약속이다. 다만 pi 공식 자료엔 "아라", "영혼", "박제" 같은 단어가 없다. 비유는 강의 안에서만 통용된다.

📗 pi의 공식 한 줄
"Pi is a minimal terminal coding harness. Adapt pi to your workflows, not the other way around, without having to fork and modify pi internals."

한국어로: pi는 미니멀한 터미널 코딩 하네스다. pi를 본인 워크플로우에 맞춰라 — 본인 워크플로우를 pi에 맞추지 말고. "가지는 AI"는 이 공식 약속의 강의용 번역이다.

왜 이게 필요한가? · 여박총피법

한 겹 더 벗기면 이건 단순한 도구 선택 문제가 아니다. ChatGPT를 잘 쓰는 사람과 본인 도구를 가진 사람의 차이는 축적 여부다. 빌려 쓰는 사람은 매 대화가 0에서 시작한다. 가진 사람은 매 대화가 자기가 쌓아온 자산 위에서 시작한다. 1년 후 둘 사이 격차는 도구 차이가 아니라 자산 차이로 벌어진다.

반대로 생각하면? · 일반지도법

pi를 안 쓴다고 죽지 않는다. ChatGPT만 잘 써도 일은 된다. 그러나 본인의 결을 가진 도구 없이 1년이 지나면, 같은 작업을 1년 전과 똑같은 시간 들여 한다. 들어간 시간이 자산이 되지 않는다. 가진다는 건 시간을 자산으로 바꾸는 결정이다.

실습 · 정과실천법
  1. 지금 본인이 자주 쓰는 AI 워크플로우 3개를 적는다 (예: 강의 자료 리서치, 옵시디언 메모 정리, 코드 리뷰).
  2. 그 중 1개를 골라 표시한다. 이게 1주 학습의 타깃 워크플로우다.
  3. 그 워크플로우를 ChatGPT로 할 때 매번 반복하는 것을 적는다 (페르소나 설명, 톤 설명, 형식 설명 등). 이게 박제 대상이다.

완료 조건: 7일 동안 만들 하네스의 타깃 워크플로우 1개가 명시됨.

다시 확인 · 반복참정법
  1. "빌려 쓰는 AI"와 "가지는 AI"의 차이를 본인 워크플로우 예시로 한 줄로 설명할 수 있는가?
  2. 이 1주 학습으로 박제할 본인의 타깃 워크플로우는 무엇인가?
  3. 그 워크플로우에서 가장 반복적으로 다시 설명하게 되는 것은 무엇인가?

모아서 나누고 분류하여 모아라. pi가 정의한 4종 커스터마이징을 정확한 이름·역할·위치로 외운다. 비유로 외우면 공식 docs와 어긋난다.

pi는 다음 4가지를 통해 본인 워크플로우에 맞게 확장된다. 4가지는 모두 파일로 박혀 npm/git으로 공유 가능하다.

이 문장이 4가지 커스터마이징의 공식 정의다. 비유 없이 그대로 외운다.

종류공식 정의파일 형식호출/적용 방식

📗 Pi Package 매니페스트 — 공식 형태 (정확히 이대로)
{
  "name": "my-package",
  "keywords": ["pi-package"],
  "pi": {
    "extensions": ["./extensions"],
    "skills": ["./skills"],
    "prompts": ["./prompts"],
    "themes": ["./themes"]
  }
}
  • keywords: ["pi-package"] 필수 — npm 검색과 pi.dev/packages 갤러리 노출용. 빠뜨리면 발견 안 됨.
  • 값은 디렉토리 경로 — 글로브와 !exclude 패턴 지원.
  • 매니페스트 없어도 OK — extensions/, skills/, prompts/, themes/ 관례 디렉토리에서 자동 발견.

⚠️ 보안 경고 (공식 — 무시 금지)
"Pi packages run with full system access. Extensions execute arbitrary code, and skills can instruct the model to perform any action including running executables. Review source code before installing third-party packages."

한국어: pi 패키지는 시스템 전체 권한으로 돈다. Extension은 임의 코드를 실행하고, Skill은 모델에게 실행파일 호출 포함 어떤 작업이든 지시할 수 있다. 서드파티 패키지 설치 전에 소스를 직접 확인하라.

🎭 강의용 비유 (pi 공식 표현 아님)
4가지아라 비유역할 비유
Prompt Templates🎴 자주 쓰는 마법 카드"같은 말 반복 비용 0"

이 비유는 워크샵에서 외우기 쉽게 쓰는 표현이다. 실제 pi docs엔 없다. 비유로 입문하되, 구현은 위 fact 박스 기준으로 한다.

왜 이게 필요한가? · 여박총피법

왜 4개로 가르나? 한 겹 벗기면 각 종류의 수정 주기가 다르기 때문이다. Prompt Template은 같은 말 반복 줄이기, Skill은 호출 가능한 능력, Extension은 외부 시스템 연결, Theme은 시각. 한 덩어리로 묶으면 매번 다 손대야 한다. 갈라 두면 필요한 것만 손댄다. 그리고 4가지 다 똑같이 ~/.pi/agent/ 아래 자기 자리에 들어간다 — 이게 pi의 일관된 약속.

반대로 생각하면? · 일반지도법

4가지 구분 없이 그냥 한 마크다운에 다 박아도 작동은 한다. 단, 다음 워크플로우 만들 때 처음부터 다시 박아야 한다. Prompt를 재활용 못 한다. Skill을 다른 봇과 공유 못 한다. 모듈러 설계의 비용은 처음 한 번 가르는 수고고, 보상은 매 사이클마다 발생한다.

실습 · 정과실천법
  1. 1장에서 정한 타깃 워크플로우를 떠올린다.
  2. 그 워크플로우를 4가지 칸으로 가른다. 종이에 4칸을 그린다 — Prompt Templates / Skills / Extensions / Themes (공식 docs 순서).
  3. 각 칸에 "이 워크플로우의 어떤 부분이 여기에 속할지" 한 줄씩 쓴다. 모르겠으면 ?. ?는 1주 미션에서 채워질 빈칸.

완료 조건: 4칸 종이가 완성되고, 각 칸이 한 줄이라도 채워짐.

5장. Day 3 — 영혼 작성 (AGENTS.md + Prompt Templates)

Part 2 · 7일 미션 · 1~2시간 (이 챕터는 천천히)
🏛️ 다산 원칙
무징불신법 無懲不信
근거 없는 것은 쓰지 않는다. 영혼은 멋 부려 쓰는 게 아니라 본인 결을 박제하는 작업이다. 본인이 안 쓰는 말은 한 단어도 들어가면 안 된다.
⚠️ v0.1 정정 — "영혼"의 실제 위치

v0.1 교재는 "Prompt Template = 에이전트의 영혼"이라고 적었다. 이건 잘못이다. pi 공식 문서 기준으로:

  • 영혼(지속적 인격·정책·컨벤션)은 AGENTS.md / CLAUDE.md (Context Files) + SYSTEM.md가 담당. 부팅 시 자동 로드 + 모든 응답에 영향.
  • Prompt Template은 /name으로 expand되는 슬래시 커맨드형 재사용 프롬프트. 특정 작업 호출용 (예: /review, /pr). 영혼이 아니라 "자주 쓰는 마법 카드".

둘 다 박는다 — 영혼은 AGENTS.md, 자주 쓰는 슬래시는 Prompt Templates.

영혼 1: AGENTS.md (자동 로드 컨텍스트)

📗 Context Files — 자동 로드 (공식)

pi는 부팅 시 다음 위치의 AGENTS.md (또는 CLAUDE.md)를 자동 로드한다:

  • ~/.pi/agent/AGENTS.md — 글로벌
  • 부모 디렉토리들 (cwd부터 위로)
  • cwd

매칭되는 모든 파일이 concat되어 시스템 컨텍스트에 들어간다. 끄려면 --no-context-files (-nc).

System Prompt 자체를 갈아끼우려면: .pi/SYSTEM.md (프로젝트) 또는 ~/.pi/agent/SYSTEM.md (글로벌). 추가만 하려면 APPEND_SYSTEM.md.

출처: README.md:296~309

본인 결을 박제하는 진짜 자리는 여기다. 자주 쓰는 말 / 안 쓰는 말 / 기본 자세 / 거절 패턴 / 결과 형식 — 이건 매번 부르고 싶지 않다. 한 번 박아두고 자동으로 들어가게 한다.

# ~/.pi/agent/AGENTS.md  (또는 프로젝트 루트의 AGENTS.md)

## 누구
타이칸의 분신 같은 에이전트. 일을 같이 하는 사이.

## 자주 쓰는 말
- "한 줄로 정리하면..."
- "결정 두 갈래..."
- "근거: ..."
- "다음 액션: ..."

## 안 쓰는 말
- "맞춤형", "여러분", "어떠신가요?"
- 영혼 없는 격언 ("성공의 핵심은...")

## 기본 자세
- 다정하지만 차분. 농담은 분위기 읽고만.
- 모르면 "모르겠어, 찾아볼게". 추측 금지.
- 본인이 안 쓰는 말투는 한 단어도 안 씀.

## 거절·반대
- "그건 아니야"라고 먼저 한 줄. 다음 줄에 이유.
- 대안 1개 같이 제시.

## 결과 형식
- 짧은 결론 → 근거 → 다음 액션 순서.
- 표·코드블록은 비교가 필요할 때만.

영혼 2: Prompt Templates (슬래시 커맨드 형 재사용 프롬프트)

📗 Prompt Template 공식 형식
<!-- ~/.pi/agent/prompts/review.md -->
---
description: Review staged git changes
argument-hint: "[focus]"
---
Review the staged changes (`git diff --cached`). Focus on:
- Bugs and logic errors
- Security issues
- Error handling gaps
- Specifically: $1

호출: /review "auth flow" → $1이 "auth flow"로 치환되어 expand.

  • 파일명이 명령어 — review.md → /review
  • description: 자동완성에 표시 (없으면 첫 줄)
  • argument-hint: <required>, [optional]
  • 인자: $1, $2, ... · $@ 또는 $ARGUMENTS (전부) · ${@:N}, ${@:N:L} (슬라이스)
  • 위치: ~/.pi/agent/prompts/, .pi/prompts/, 패키지, settings
출처: docs/prompt-templates.md

본인 자주 쓰는 작업 3~5개를 슬래시 커맨드로 박는다 — 예: /review, /summarize, /journal. AGENTS.md가 "어떻게 답하는가"라면, Prompt Templates는 "어떤 작업을 자주 부르는가"다.

왜 이게 필요한가? · 여박총피법

"프롬프트 잘 쓰는 법"의 한 겹 아래엔 더 중요한 게 있다. 매번 같은 톤을 다시 설명하는 게 진짜 비용이다. 프롬프트 엔지니어링이라 부르는 것의 80%는 본인 결을 매번 다시 박는 일이다. 한 번 AGENTS.md에 박으면 그 비용이 사라진다. 그 위에 자주 쓰는 작업은 Prompt Template으로 한 번 더 박는다. 이게 "영혼을 가진다"의 실용적 의미다.

AGENTS.md 없이 능력만 만들면? 능력은 잘 작동한다. 그러나 같은 능력을 다른 LLM에 붙여도 결과가 똑같다. "내 것"이라는 감각이 안 생긴다. 가지는 AI의 본질이 빠진 채로 도구만 본인 폴더에 두는 셈.

실습 · 정과실천법

  2. 최근 카톡·메모 5문장으로 톤 검증 — AGENTS.md 톤과 일치하는가? (20분).
  3. Prompt Template 1개 작성 — 본인이 가장 자주 하는 작업 1개 (예: 강의 자료 리서치 / PR 리뷰 / 일기 정리) (20분).
  4. 호출 시연 — pi 부팅 → 동일 질문을 AGENTS.md 적용 전/후로 던져보고 톤 변화 확인.

📗 Extension Quick Start (공식 예제)
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

export default function (pi: ExtensionAPI) {
  // 1) 이벤트 구독
  pi.on("session_start", async (_event, ctx) => {
    ctx.ui.notify("Extension loaded!", "info");
  });

  // 2) 위험 명령 게이트
  pi.on("tool_call", async (event, ctx) => {
    if (event.toolName === "bash" && event.input.command?.includes("rm -rf")) {
      const ok = await ctx.ui.confirm("Dangerous!", "Allow rm -rf?");
      if (!ok) return { block: true, reason: "Blocked by user" };
    }
  });

  // 3) 커스텀 tool 등록
  pi.registerTool({
    name: "greet",
    label: "Greet",
    description: "Greet someone by name",
    parameters: Type.Object({
      name: Type.String({ description: "Name to greet" }),
    }),
    async execute(toolCallId, params, signal, onUpdate, ctx) {
      return {
        content: [{ type: "text", text: `Hello, ${params.name}!` }],
        details: {},
      };
    },
  });

  // 4) 슬래시 커맨드 등록
  pi.registerCommand("hello", {
    description: "Say hello",
    handler: async (args, ctx) => {
      ctx.ui.notify(`Hello ${args || "world"}!`, "info");
    },
  });
}

export default는 async도 가능 — 부팅 전 원격 모델 목록 가져오는 등 일회성 초기화에 유용.

왜 이게 필요한가? · 여박총피법

외부 데이터에 닿지 못하는 능력은 절반짜리다. 본인 옵시디언, 본인 캘린더, 본인 깃 레포 — 본인 자산에 닿게 하는 통로가 Extension. 한 겹 더 벗기면, Extension이 곧 본인 시스템과 pi를 잇는 다리다. 다리가 없으면 pi는 본인 결을 모르는 상태로 응답한다. 그리고 Extension은 단지 도구 추가가 아니다 — tool_call 이벤트를 가로채서 권한 게이트, 자동 커밋, 위험 명령 차단 같은 정책도 박을 수 있다.

import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";
import { Type } from "typebox";

export default function (pi: ExtensionAPI) {
  pi.registerTool({
    name: "{tool-name}",
    label: "{Display label}",
    description: "{What it does — agent reads this}",
    parameters: Type.Object({
      input: Type.String({ description: "Input description" }),
    }),
    async execute(toolCallId, params, signal, onUpdate, ctx) {
      // 본인 로직
      return {
        content: [{ type: "text", text: `Result: ${params.input}` }],
        details: {},
      };
    },
  });

  // 선택: 슬래시 커맨드
  pi.registerCommand("{cmd-name}", {
    description: "{Command description}",
    handler: async (args, ctx) => {
      ctx.ui.notify(`Got: ${args}`, "info");
    },
  });

  // 선택: 이벤트 후크
  pi.on("tool_call", async (event, ctx) => {
    // 권한 게이트, 로깅 등
  });
}
